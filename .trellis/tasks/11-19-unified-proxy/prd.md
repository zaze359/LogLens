# 统一抓包代理：单一监听 + 设备自动配置 + 分流显示

## Goal

把内建抓包代理收敛为**进程内唯一的监听器**。任何把代理指向它的客户端都由它接收；
设备页的「开始/关闭抓包」退化为**自动设置/还原设备代理配置**，仅起配置作用；
收到的流量按来源 IP **分流**到对应设备页，未绑定来源归入独立代理页。

## Background

现状有两个互相独立的监听器，导致同机并存时端口漂移：

- 设备采集走 `AppState::proxy_hub()`（`ProxyHub::new()`，未登记来源直接 403）。
- 独立代理走 `AppState::proxy_server`（`ProxyServer`，自带一个 `ProxyHub::with_enroll`）。

两者各自 `bind` 一个端口。独立代理先占用 18999 后，设备采集 `bind` 失败 → 回退到系统
随机端口，于是出现「代理 172.21.32.185:18999 / 采集端点 172.21.32.185:52523」。

## Requirements

### R1 唯一监听器

- 进程内同一时刻最多只有一个代理监听 socket。
- 「开启独立代理」与「设备开始抓包」**共用同一个监听器**，不再各自 bind。
- 前者未开启时，设备开始抓包会自动拉起该监听器；反之亦然。
- 端口恒为 `18999`（被外部程序占用时的回退策略保持现有行为）。

### R2 统一接收

- 任何把代理指向 `<lan>:18999` 的客户端都会被接收，不再出现「拒绝未登记来源 403」。
- 未绑定设备的来源按来源 IP 分组，归入独立代理页。

### R3 设备抓包退化为配置动作

- 设备页「开始原生接口采集」= 在共享代理上**登记该设备（serial + IP）** + 自动设置设备代理。
- 不再创建新监听、不再有独立的 `ProxyCapture` 监听生命周期。
- 关闭抓包 = 解除登记 + 还原该设备代理配置；**共享代理继续运行**，不影响其它设备与独立代理。
- 若监听器是仅因该设备而拉起的、且已无任何来源在使用，允许随后关闭（不影响已绑定设备）。

### R4 分流显示

- 按请求来源 IP 精确匹配到已登记设备 → 该请求归入对应设备页。
- 未匹配到任何设备 → 归入独立代理页。
- 设备页只显示自己的请求；独立代理页只显示未绑定来源的请求。
- 同一 IP 同时只归属一个设备；重复登记需给出明确错误。

### R5 兼容

- H5（CDP）采集行为不变，仍与原生流量合并展示在同一设备表格。
- 导入 HAR / JSONL 行为不变。
- 设备代理的残留自愈、journal、退出还原逻辑不变。

## Constraints

- 不引入新的外部依赖（保持 `proxy.rs` 的「零 HTTP/TLS 库」特性）。
- 遵守 `.trellis/spec/backend/logging-guidelines.md`：流程日志只记计数/ID，不记 URL、正文、头部。
- UI 文案、注释、错误信息用中文。
- 现有 `cargo test --lib` 的 124 个用例必须保持通过。

## Acceptance Criteria

- [ ] AC1 单监听：启动独立代理后再让设备开始抓包，两者 `endpoint` 完全相同（均为 18999），`lsof` 只看到一个 LISTEN。
- [ ] AC2 统一接收：一个不在 `adb devices` 里的客户端（如 curl）指向该端点，请求被接收并出现在独立代理页，而非 403。
- [ ] AC3 配置语义：设备「开始抓包」只写设备代理设置，不再新开 socket；关闭后设备代理被还原，且若独立代理仍开启，其 `endpoint` 不变、仍可继续收包。
- [ ] AC4 分流：设备 A 的请求只出现在 A 的页面，独立代理页不出现 A 的请求；未绑定来源只出现在独立代理页。
- [ ] AC5 回归：H5 采集、HAR/JSONL 导入、设备代理自愈行为不变，`cargo test --lib` 全绿。
- [ ] AC6 校验：新增测试覆盖 R1/R3/R4 的关键分支，且真实 curl 端到端跑通。

## Out of Scope

- HTTPS 解密（仍只记录 CONNECT 的域名/SNI/字节数）。
- 多网卡同时监听（仍绑定单一 LAN 地址）。
- 代理认证、白名单等访问控制。

## Decisions

- **监听器生命周期：常驻**。一旦被「开启独立代理」或「设备开始抓包」拉起，就保持 LISTEN
  直到用户手动关闭或应用退出。设备全部关闭/解绑不触发关闭，端口因此稳定不变。
  这同时消掉了一个既有一致性问题：原 `ProxyHub::detach` 在最后一个设备离开时会关闭
  socket，导致下次开抓要重建监听、端口可能漂移。
