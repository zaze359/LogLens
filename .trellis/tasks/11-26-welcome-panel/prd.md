# 首页引导面板

## Goal

冷启动时不要直接摊开一屏空荡荡的日志面板（规则侧栏 / 筛选栏 / 时间轴 / 空表格 / 状态栏），改为一屏清爽的引导面板，让用户在两步内知道「打开日志文件」或「连接设备」；日志面板在真正有日志时才出现。

## Background（已确认事实）

- `App.vue:31-34` 的 `logVisible` 在本地工作区恒为 `true`，所以冷启动时整块 `LogPane` 直接铺满。
- `LogTable.vue:221-243` 的空状态只有一行提示 + 代理状态小条；首页其余部分都是与「还没有日志」无关的重型控件。
- `App.vue:59-73` 已在应用级注册原生拖放，拖入文件可直接 `loadFile`，不依赖日志面板挂载。
- 文件 / 设备入口分别由 `pickAndLoadFile()` / `openDevicePicker()` 提供（`stores/session.ts`），浏览器预览下这两个函数已有提示保护。
- 工作区状态都在 store：`tabs`、`deviceWorkspaces`、`deviceView`；关闭最后一份日志 / 设备工作区后它们都会回到空。
- 项目规范：有状态的面板用 `v-show` 常驻挂载，样式统一放 `src/styles/main.css`，用既有 CSS 变量与按钮类。

## Requirements

- R1 新增一个首页引导组件（`src/components/WelcomePanel.vue`），在无日志、无设备工作区、不在设备视图时替代日志面板显示；日志面板继续 `v-show` 常驻挂载，不被卸载。
- R2 引导面板提供两个主操作：「打开日志文件」（`pickAndLoadFile`）与「连接设备」（`openDevicePicker`），文案说明各自能得到什么。
- R3 引导面板提示可把日志文件直接拖进窗口（拖放逻辑复用现有应用级监听，不新增监听）。
- R4 保留原来首页空状态里的独立代理状态与入口（运行中显示地址 / 来源数并可「查看请求」，未开启时可「开启代理」），避免这次调整悄悄丢功能。
- R5 一旦打开日志或设备工作区，引导面板立即让位；关掉最后一份日志和最后一个设备工作区后，引导面板回来。
- R6 样式只用现有 CSS 变量与全局类（`btn` / `btn-primary` / `muted` 等），不新增依赖、不写 `<style scoped>`，不改 store/IPC/Rust 侧。

## Acceptance Criteria

- [ ] AC1 冷启动（无 tab、无设备工作区）看到的是引导面板，看不到规则侧栏、筛选栏、时间轴、日志空表格。
- [ ] AC2 引导面板上「打开日志文件」「连接设备」两个按钮可用，且拖入日志文件的提示可见；代理状态与入口与原首页一致。
- [ ] AC3 打开文件后直接进入日志工作区，引导面板消失；打开设备工作区后进入设备视图，引导面板消失；关闭所有工作区后引导面板重新出现。
- [ ] AC4 浏览器预览模式仍显示原有横幅，点击原生功能按钮沿用 store 里的既有提示，不出现新报错。
- [ ] AC5 `npm run build`（含 `vue-tsc --noEmit`）通过。

## Out of Scope

- 首次启动的「已看过引导」持久化标记、多步向导、示例日志一键打开按钮。
- 改动标签条、设备工具 rail、代理面板本身的行为。
- 任何 IPC / Rust / store 数据结构变更。
